# 设计与取舍

先读 [接入协议](../../references/protocol.md)，读取任务上下文及既有设计的最新版本。

- 以已确认需求和已采用的原则版本为基线；可针对草稿探索方案，但明确标记依赖未确认内容。不要用原则最新草稿替代任务采用的版本。
- 按实际复杂度维护一份或多份 `design`：category 为 architecture/module/interface/testing/decision。正文支持 Markdown，说明目标、方案、关键接口、取舍、风险与验证方式。
- 引用相关 REQ、AC、PRN 编号及版本，避免复制整份需求。在必要时附已有代码位置或接口资料，并区分事实与待实现设计。
- `required` 表示本期验收必需设计。标准任务至少需要一份必需设计；不要改成轻量流程或将已有必需项降级来消除缺口。
- 更新已有设计使用刚读取的 expectedVersion；仅提交用户授权范围内的变化，再对保存后的版本调用 request_review。

需要 Owner 取舍的内容写成 question，给出可比较的选项与影响。结束时返回设计编号、主要决策和待确认点，不自动批准设计、部署代码或关闭任务。
