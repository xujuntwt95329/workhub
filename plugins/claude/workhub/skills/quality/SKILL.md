# 测试与证据

先读 [接入协议](../../references/protocol.md) 和 [质量证据规则](../../references/quality-evidence.md)。

1. 用 get_task_context 和 get_quality_matrix 读取当前范围、缺口及 traceability；对无标准需求先指出需求缺口，不擅自编造已获认可的验收条件。
2. 查询并复用已有 `check`（界面称测试用例），用 criterionIds 关联明确的标准 UUID。一个用例可关联多个标准，一个标准可由多个必需用例覆盖。
3. 编写可执行的前置条件、步骤、预期结果与自动化定位。新用例可先未关联，但必需用例未关联会阻止验收。新/改用例提交 request_review。
4. 按证据规则获取运行前版本，实际运行测试，再追加 `result`。不能覆盖旧结果、把计划当执行、把未运行当通过，或为消除过期提示补填未经测试的新版本。
5. 失败记录 issue，关联 checkIds；解决和复核按事实更新状态，不把开发者自报解决自动当成验证通过。
6. 重新读取矩阵，简要报告通过、失败、未验证、待复验、范围外及未覆盖项，给出记录编号与证据。

测试环境或执行能力不可用时，可以提交计划和阻塞说明，明确没有执行；不要提交 passed，不自动豁免、不降低必需标记、不替 Owner 验收。
