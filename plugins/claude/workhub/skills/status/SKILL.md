# 进度与覆盖总结

先读 [接入协议](../../references/protocol.md)。默认只读，不为了生成总结创建记录或改变任务状态。

- 定位具体任务后读取 get_task_context、get_quality_matrix。需要工作空间概览时先列出授权范围内的任务，再按问题读取相关任务；不能把凭证看不到的内容当成不存在。
- 区分实施进度、需求确认进度和质量覆盖。工作项完成不等于验收通过；用例关联率、执行覆盖率、通过率是不同指标，使用服务端口径。
- 引用关键 REQ/AC/CHK/RUN/ISS 编号和版本。最新失败覆盖旧通过；旧版本结果只能作为历史，不能作为当前通过证据。
- 拒绝/删除需求和范围外用例与当前范围分开说明；必要时 list_records 查看历史。未采用原则更新、未确认设计、未解决阻塞和证据缺口分别说明其影响。
- 给出简明的整体状态、少量关键依据及下一步建议；用户有明确问题时直接回答。不要把模型判断表述成 Owner 已批准或系统已验收。

可按用户要求保存报告快照或修改内容，但须使用实际提供的接口和相应权限；只读请求不自动调用内置付费助手。
